## Added scope and regressions

- Haptic → Move: both native Actions/Mapping and cue paths use the same scoped handoff. The whole Haptic pair ends, the valid Move launches once, unrelated owners persist. Invalid targets do not cancel an unrelated prior command. The old blanket-rejection expectation is intentionally replaced; no Haptic-plus-Move composition is claimed.
- Curve fitting: 191 checks span 0.05/3/300-second durations, narrow/large/negative ranges, all points/Bezier handles, small fixed sizes and byte-identical serialization after display operations. Rendered native screenshots are retained.
- Recorder: 33 dedicated checks cover genuine accepted reply timestamps, raw integrity, gaps/dwells/reversals, explicit reversible conversion, shared playback completion/End and inert reopening. The integrated Recorder UI also captures real fake-driver replies and creates an editable curve.
- Existing native, V0.1, multi-motor, integration/range, pinned reference-packet parity and 17 Python tests run afresh. Compatibility uses 12 copied milestone/production documents; derivatives replace adapters with fake endpoints and clear physical MIDI device selections. Original files are only read.
- Windows worker regression: the unchanged `>10` worker-loop assertion during a 120 ms GUI stall exposed coarse waits (7 iterations in 123.7 ms). A private high-resolution waitable timer restored 29 iterations in 124.1 ms. No assertion was relaxed. The failed result is preserved in `worker-coarse-wait-before.txt` and `regressions-before-worker-fix.json`. This is an observed local timing improvement, not a real-time guarantee. [Microsoft timer API](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-createwaitabletimerexw), [relative wait semantics](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-setwaitabletimer).

## Evidence limits

The full 15-suite regression pass uses the final execution/editor implementation. Later changes are limited to startup layout and the application-name override; the delivered executable is checked separately against a copied fake-only show. Startup smoke seeds only the new product namespace lastVersion, as native fixtures do, so the upstream web Welcome dialog does not obscure the project window. Existing Integration/Native POC namespaces are untouched.

**RUN:** native fake-output application tests; actual Windows audio playback/callback clock; native integrated dock panels, actual button callbacks, editor focus, recorder, song controls, PNG inspection; save/reload with embedded song/package assets; current executable/source identity; preservation hashes.

**BLOCKED:** mouse-driven desktop automation. The bundled Computer Use helper returned `native pipe is unavailable (os error 2)` on initial call, retry, kernel reset/retry, and the alternative CUA inventory. No mouse-driven UI result is claimed. Native component tests and visual renders completed without that helper.

**NOT RUN:** physical cupboard guiding/reproduction accuracy, live CAN/serial motors, real MIDI/light devices, installed motor firmware transitions, loaded mechanical timing, long-duration show soak, non-Windows builds, or QLab on macOS. These are report statuses, not application restrictions. The software does not present a physical test as passed or disable direct operation because it is unverified.

First physical session remains an operator task: use a copy of a show, confirm the actual selected model/firmware and configured MIN/MAX/reference/effort, then observe automatic Haptic pair handoff, record one cupboard, inspect the original/gaps and authored absolute start, and evaluate its playback and exact End. Do not infer RS01 firmware equivalence from an RS02 manual or software packets. Do not replace the preserved installation automatically.
